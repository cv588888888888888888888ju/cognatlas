# 大型项目文档层链设计

库小的时候，「按目录放」就够了；长到几百篇以后，问题从「东西在哪」变成「哪份是准的、从哪开始读」。这页给一套分层与链接规则，按需取用，不要一次全上。

## 四层结构

| 层 | 作用 | 放什么 | 更新频率 |
|---|---|---|---|
| **L0 索引** | 入口与地图 | 每个领域一个目录页，列子文档与一句话摘要 | 低，新增文档时补一行 |
| **L1 规范 / 决策** | 约束与理由 | Policy、架构决策、接口契约、门禁规则 | 低，变更需记录 |
| **L2 主题 / 模块** | 具体知识 | 实现细节、踩坑、方案对比、操作步骤 | 中 |
| **L3 证据 / 原始** | 可追溯材料 | `_raw/`、快照、日志、外部原文 | 只追加，不改写 |

L3 不做 frontmatter 治理，也不要求链接；它只负责「当时到底发生了什么」。

## 链接方向

- L2 文档**向上**链到它遵守的 L1 规范（「见 [[30.12-能力设计与投放]]」）。
- L0 索引**向下**链到 L1/L2，每行一句话说明「为什么点它」。
- 反链不要手工维护：指向上级后，上级的反链面板会自己长出来。
- 不要横向链一堆同层碎片；同层关系交给标签或索引页。

## 每篇文档的链接预算

- 出链 3–8 条：少于 3 条通常说明它还没接入网络；多于 8 条时，考虑拆一个索引页。
- 入链 > 10 条：说明它是热点，检查是否该升级成 L1（规范/索引）。
- 入链 = 0：不是错误，但要在下一次整理时决定「链进去」或「归档」。

## 目录长什么样

```text
30-Agent工程/
  30.0-Agent工程索引.md      ← L0：全领域地图
  30.12-能力设计与投放.md    ← L1：规范
  30.11-Agent工具链踩坑实测.md ← L2：具体知识
  _raw/                      ← L3：原始记录
```

索引页的最小模板：

```markdown
# Agent 工程索引

- [[30.12-能力设计与投放]] —— 设计能力时的顺序与投放判据。
- [[30.11-Agent工具链踩坑实测]] —— 本机工具链的真实故障与修法。
- [[30.7-多Agent并行协作]] —— 并行协作的边界与写法。
```

## 从单层迁到分层

1. **先加 L0**：每个一级目录建一篇索引，只写链接与一句话；不改原有文档。
2. **再补向上链接**：每篇 L2 至少链一条 L1；一次性批量补容易错，按目录分批。
3. **最后收紧 L1**：把互相矛盾的规范合并成一篇，其余标 `deprecated` 并链到新篇。
4. 每次只做一层，做完跑一次 `kb status` 与检索抽查，确认没有把链接改断。

## 判断「该不该拆」

- 一篇文档出现两个以上互不依赖的主题 → 拆。
- 同一主题在三个地方各写一半 → 合。
- 文档超过约 800 行，且检索时经常只命中其中一节 → 拆，并在原位置留索引链接。

## 检查清单（每季度一次）

- [ ] 每个一级目录都有 L0 索引，且索引里的链接都能点开。
- [ ] 没有 L2 文档直接链到 L3 文件路径（应链到说明文档）。
- [ ] 入链为 0 的文档已处理（链接或归档）。
- [ ] 过期文档要么更新 `stale_after`，要么标 `deprecated`。
- [ ] 同义标签已合并，检索 `tag:` 时不再出现两个写法。
